# Challenge solution

## Investigation

The app is a build-free HTML/CSS/JavaScript board. `index.html` defines the UI,
`style.css` controls layout and themes, and `script.js` manages tasks and localStorage.
The challenge instructions remain in `README.md`.

History was examined using `git log --all --oneline` and diffs between versions:

| Version | Commit | Finding |
| --- | --- | --- |
| 1 | `71e92f2` | `.board-section { display: none }` hides the task board. A browser regression test confirmed this failure. |
| 2 | `596210e` | Removes that rule. The board, task grouping, progress calculation and theme toggle work. This is the restoration baseline. |
| 3 | `bf77b31` | Breaks status filtering, reports an impossible completed count, forces progress to 100%, and stops the theme button switching themes. |
| 4 | `19bf8e9` | Repairs the JavaScript but covers the page with a blocking "WRONG VERSION" overlay. The browser regression test confirmed the obstruction. |

Restoration uses the three application files from Version 2, preserving subsequent
README/history rather than resetting the branch. The changes are on `fixed-website`.

## New feature: focus timer

- Defaults to a 25-minute session, with an adjustable whole-minute duration of 1–120.
- Start, pause, resume and reset; completion leaves a visible, screen-reader-announced notice.
- Uses an absolute deadline instead of subtracting one second per callback, so delayed
  callbacks/background-tab throttling do not extend the session. A suspended browser
  cannot deliver a notice until it runs again; the countdown catches up then.
- Duration is locked during running/paused sessions. Reset unlocks it.
- Timer state is independent of task operations. Tasks retain their existing localStorage behavior.
- Timer is session-only: reloading resets it. This is stated in the UI.
- Fits mobile and desktop and uses the existing light/dark theme.
- No runtime dependencies, permissions, audio or notification access required.

The implementation is isolated in `focus-timer.js`. The proposed search feature was
replaced with the requested focus timer and is not part of this submission.

## Run

Open `index.html` in a modern browser. No build is required.
For a local HTTP preview, run `node tests/server.cjs` and visit `http://127.0.0.1:4173`.

## Verify

Node.js 20+ is needed only for the development test tools:

```sh
npm ci
npx playwright install chromium
npm test
```

The tests run against a loopback-only static server that exposes only the app assets.
They use fresh browser contexts and a controlled clock, and do not touch real task data.

The 11 Chromium tests cover: the unobstructed board; task columns and progress;
create/edit/move/delete and persistence; drag-and-drop; theme persistence; clearing
completed tasks; empty/malformed storage; timer start/pause/resume/reset;
custom duration/completion/restart; invalid durations; and mobile/desktop layout in both themes.
Screenshots are generated by the responsive-layout test under ignored `test-results/`.

Red/green checks were run before implementation: the current overlay and Version 1's
hidden board failed the baseline test; Version 2 passed. The timer tests first failed
because the controls did not exist, then passed with the implementation.
